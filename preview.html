How to use Frame

A no-build UI kit for client apps: tight, accessible, fast. Themes and vocabulary borrowed from daisyUI.

README
Quick startThemingApp shell & logoComponentsBehaviour (frame.js)Pages & templatesAgentsQuality rules

Quick start

Up and running in a minute.

Three links, no build, no npm, no Python. Works from a folder, a CDN or any static host.

<!doctype html>
<html lang="en" data-theme="pine">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <link rel="stylesheet" href="frame.css">
  <link rel="stylesheet" href="themes/pine.css">   <!-- ONE theme file, light + dark (10 to choose from) -->
  <link rel="stylesheet" href="theme.css">         <!-- optional: this client's own colours -->
  <script src="frame.js" data-sprite="icons.svg" defer></script>   <!-- add data-check while building -->
</head>
<body class="f-root">
  <div class="f-app f-app--side"> … </div>
</body>
</html>

Starting a client project

  1. Copy the folder into the project (or host it and link from the URL).
  2. Pick a theme: link themes/NAME.css. For the client's own colours copy theme.example.css to theme.css and set primary, accent and neutral hue.
  3. Copy the pages you need from pages/; pick a shell, sidebar or top-nav (see starter.html).
  4. Check: add data-check to the frame.js script tag and open the page. The console lists problems; Frame.check() returns them.

Theming

Colours, corners, density, dark mode.

A theme is a block of daisyUI-compatible --color-* variables. Everything else (hover, tints, borders, status colours, dark text) is derived.

/* theme.css: the whole per-client file */
[data-theme="acme"] {
  --neutral-hue: 300;
  --color-primary: #7a1fa2;  --color-primary-content: #fff;
  --color-accent:  #ffe14d;  --color-accent-content:  #1d1800;
}

Paste any block from the daisyUI theme generator instead if the client wants a full custom palette. Or pick one of the themes/NAME.css files (see the Themes page).

Switches on <html>

AttributeValuesEffect
data-themepine · indigo · ink · terracotta · ocean · any daisyUI nameColours. Link the one matching themes/NAME.css
data-modelight · darkWorks with EVERY theme: each has a generated light and dark version. Or Frame.setMode('auto') to follow the OS
data-radiuscrisp · squareCorners. Square also docks the panels to the screen edges
data-layoutfloating · dockedFloating panels on a canvas, or flush hairline panels
data-densitycompactTighter rows and controls (0.85)

Roles every colour plays

TokenUsed for
--color-primaryButtons, active nav, selected states, hero card. One per app
--color-accentONE highlight per screen: the next best action
--color-secondaryAI / assistive features
--color-base-100/200/300Card surface · page canvas · inset and borders
--color-success / warning / error / infoStatus. Always paired with an icon or label, never colour alone
--radius-box / field / selectorCards · inputs and buttons · pills (daisyUI contract)

Logo placement

Three slots, set once per client: .f-logo (sidebar, 28px), .f-logo--mark (top bar, square mark only) and .f-logo--lg (sign-in). Give each a square mark and an optional wordmark; the Settings page shows the upload UX. For dark mode add a white wordmark in .f-logo-dark.

Behaviour

Data-attribute API.

frame.js is optional and has no dependencies. Everything is a data-attribute, so pages stay plain HTML an agent can read.

AttributeDoes
data-f-open="#id"Opens a dialog (modal, drawer, command palette)
data-f-closeCloses the dialog it sits in
data-f-menu="#id"Toggles a dropdown; data-align=end|center
data-f-tabsOn a container: its children with aria-controls switch panels
data-f-select / data-f-row / data-f-allRow selection and the bulk action bar
th[data-sort]Click-to-sort columns (td[data-v] holds the raw value)
data-f-filter="#grid"Live-filters children by their data-f-text
data-f-wizard / data-f-next / data-f-prevMulti-step form
data-f-copy="text"Copies text and shows a toast
data-f-theme="name"Switches the theme (theme gallery)

Built for any agent

Claude, Codex, Cursor, Copilot, Grok, local models.

Frame is meant to be built with by AI agents. Point the agent at the folder or at a hosted link and say what to build.

Two ways to point an agent at it

Where the kit isTell the agent
In the project folder (e.g. frame/)“Build the Suppliers screen. Read frame/AGENTS.md first.” Agents that auto-read AGENTS.md or CLAUDE.md find it by themselves: paste AGENTS.snippet.md into the project’s own AGENTS.md
Hosted at a URL“Build the Suppliers screen. Read https://HOST/llms-full.txt first and link the kit from https://HOST/.” One document holds the rules, every component with markup, behaviours, themes, icons and a working starter

Hosting is any static host (GitHub Pages, Cloudflare Pages, Netlify, S3) or a public GitHub repo served through jsDelivr. The bundled _headers enables the cross-origin icon sprite.

What is in the kit for agents

FileFor
llms-full.txtEverything in one document. Best when the agent can only fetch URLs
llms.txtShort index and the three link tags
AGENTS.mdRules and workflow. Read automatically by Codex, Cursor, Copilot, Claude Code and most coding agents
CLAUDE.md · .cursor/ · .github/One-line pointers so each tool finds AGENTS.md
SKILL.mdThe same as a packaged agent skill
components.jsonEvery class, modifier, example and daisyUI name, machine-readable
icons.json · themes.jsonEvery icon (name, tags) and theme
frame.js data-checkValidator that runs in the browser: unknown classes, missing icons, unlabeled controls, daisyUI/Tailwind class names. Frame.check() returns the list

Python is only for maintaining the kit itself (tools/icons.py, tools/themes.py, build.py). Building an app never needs it.

Quality rules

Accessible, responsive, fast by default.

The defaults every Frame app keeps, so clients get fast, accessible apps without a review round.

AreaRule
AccessibilityEvery icon-only button has aria-label. Status is icon + text, never colour alone. Focus ring is never removed. Dialogs are native {M('<dialog>')} (focus trap, Esc). Tabs and menus use ARIA roles.
ContrastText on surfaces meets 4.5:1 in light and dark. Primary and accent always ship with their -content colour.
ResponsiveContainer queries on cards, tables scroll inside {M('.f-tablewrap')}, sidebar collapses to an icon rail under 900px.
PerformanceNo framework, no build. Link one theme file (about 2 KB), not all 40. Fonts: 2 weights, display=swap. frame.css ≈ 72 KB, gzip ≈ 15 KB.
MotionRespect prefers-reduced-motion. Micro-animations only on transform and opacity.
ChartsUse the fixed {M('--chart-1..4')} palette; never the brand colour as a series.
